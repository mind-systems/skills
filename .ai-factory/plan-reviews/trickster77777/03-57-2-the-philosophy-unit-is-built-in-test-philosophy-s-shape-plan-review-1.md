### Findings

**1. The direct-invocation input contract is unpinned, and two frontmatter fields ride on it.**

The plan pins the omission of `argument-hint` on precedent: "No `argument-hint` (the precedent carries none)". The precedent does not carry the case. `test-philosophy` takes no input at all — it is loaded so its one discriminator is in context, and the caller supplies everything. The unit being created here explicitly does take input in one of its two modes: the pinned body itself says "a direct invocation, naming a region, reaches it through the space entry" and "the user supplies the route himself, naming a region and what raises suspicion".

Measured across `src/skills/` (all 24 frontmatters read): every skill that takes an input carries `argument-hint`. The only skills without it are the four engines that are `user-invocable: false` (`roadmap-engine`, `orchestrator-artifacts`, `architect-editor-engine`, `architect-pairing-engine`), `test-philosophy` (user-invocable, no input), and the unsymlinked `ui-ux-pro-max`. `polymorphism-philosophy` would be the repository's only user-invocable, input-taking skill without one — and `CLAUDE.md` § "SKILL.md frontmatter (required fields)" lists the field among the required four.

Failure scenario: the user types `/polymorphism-philosophy` with nothing after it. The space entry is the whole reason the unit is user-invocable, and it needs a region; with no hint the user gets no indication that a region is what the slash command wants, and the agent either guesses one or has to ask — which is what `agent-architect`'s own hint (`"[unit of work — e.g. a phase, a task, a file]"`) exists to prevent for exactly the same shape of input.

The same undecided question reaches `allowed-tools: Read`, copied from the precedent in the same move. If the region arrives as conversational context with a caller holding its own tools, `Read` is right. If it arrives as `$ARGUMENTS` naming "a module, a directory" — the body's own words — then `Read` alone cannot enumerate declarations in a directory, and the space entry cannot run from a direct invocation without `Grep`/`Glob`.

This is one decision with two consequences, and neither the spec nor the plan makes it. It is not the implementer's to make either: the spec pins the frontmatter block verbatim, so an implementer following the plan cannot add the field without deviating. The options, stated not resolved: (a) the direct-invocation region arrives as `$ARGUMENTS` → the pinned block gains `argument-hint` and the tool set is re-examined; (b) it arrives as surrounding conversation, the precedent carries after all → the plan says so in one sentence on that ground instead of on "the precedent carries none", which is the claim that does not hold.

**2. The symlink step's verification cannot fail on the failure it exists to catch.**

The spec's first blast-radius rule requires that "the symlink target must resolve." The plan's verify for that step is the name sweep — `ls src/skills/ active/skills/ 2>/dev/null | grep -i "polymorphism-philosophy"` — read as "the sweep above now returns exactly two entries — the real directory and a symlink resolving to it".

`ls` on a directory prints an entry's *name*; a dangling symlink and a live one are byte-identical in that output. Failure scenario: the `ln -sfn` target is written with a typo (or with the wrong relative depth — `../src/skills/…` instead of `../../src/skills/…`, which resolves to nothing from `active/skills/`). `ls active/skills/` still prints `polymorphism-philosophy`, the sweep still returns exactly two lines, the invariant reads satisfied, and the task closes. Nothing then errors: `~/.claude/skills` → `active/skills` simply has one entry Claude Code cannot load. By `test-philosophy`'s own discriminator this is the silent-failure class — no compiler, no exception, no 4xx, just a skill that is never there — which is precisely why the check is worth writing rather than the loud kind the plan is right to omit elsewhere.

The plan inherits the hole from the spec's sweep rather than introducing it, but it is closable inside this task's own boundary with one command that dereferences instead of listing — e.g. `head -1 active/skills/polymorphism-philosophy/SKILL.md` returning `---`, or `test -e active/skills/polymorphism-philosophy`.
