### Critical Issues

**1. The plan never says why a file that declares itself final may be edited — and the plan is all the implementer reads.**

`docs/reserved-words.md` line 1, before the title, is:

```
> This document is final and is not subject to update.
```

Both artifacts above the plan pre-empt this deliberately. The contract line: "The file's opening line forecloses updating its meanings, and this removes a collision its own rule already forbids rather than changing one." The task spec, under its own § "Blast radius": "This is not an update to the registry's meanings, which its opening line forecloses. It removes a collision the registry's own bidirectional rule already forbids — the document is being made to obey itself, and the set of terms it binds is unchanged."

The plan carries neither sentence, and does not mention the banner at all. Its § Context stops at "violating its own 'one word, one meaning' rule. This task removes the phrase from the task-spec entry so the word names exactly one thing."

This matters because of who reads what. `orchestrator/orchestrator/prompts/implementer.md` § "Step 0"/"Step 1" has the implementer read `.ai-factory/ARCHITECTURE.md`, `.ai-factory/RULES.md` (absent here) and **the plan file** — not the roadmap line, not the task spec. The rationale that exists twice upstream exists nowhere in the implementer's context. Worse, the banner is not something the implementer might miss: the grove root `CLAUDE.md` imports the whole file with `@skills/docs/reserved-words.md`, so "This document is final and is not subject to update" is already in the always-loaded layer of the session before the implementer opens anything, and it is the first line it meets when it does.

Failure scenario: the implementer opens `docs/reserved-words.md`, meets a first line that forbids the change its plan orders, and has nothing in its context that reconciles the two. That is precisely the shape the escalation engine describes — an unresolved disagreement between two documents that nothing in reach settles — so the honest move available to it is to write `ESCALATION` and halt the run over a question the task spec already answered. The cheaper failure is a wasted round asking. The expensive one is an implementer that resolves the conflict the other way and leaves the task undone.

Repair: put the licensing sentence in § Context, in the plan's own words but carrying the spec's claim — this is not an update to the registry's meanings, which the opening line forecloses; it removes a collision the registry's bidirectional rule already forbids, and the set of terms bound is unchanged. One sentence, and the conflict never reaches the implementer as a conflict.
