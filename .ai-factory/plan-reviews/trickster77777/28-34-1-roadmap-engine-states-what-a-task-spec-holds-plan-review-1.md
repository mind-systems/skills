### Critical Issues

1. **`src/skills/roadmap-engine/SKILL.md` — the sweep behind "nothing else has to move" is string-level, and a direct caller restates the dropped enumeration in prose.** The plan states: "Verified at plan time: this is the only occurrence of that enumeration in the repository outside `.ai-factory/` — no skill, command or doc restates it, so nothing else has to move with it." The first half is true of the literal string; the inference is not. `src/skills/roadmap-decompose/SKILL.md:88–89` — hook (d), "Decompose existing" — reads: *"Register an added update-menu action: expand a vague task into a full spec (what exists today, the exact change, files/types/methods to touch, guards, how to verify)."* In that file "full spec" is the task spec (same phrase at `:30` and `:107`, both citing `roadmap-engine`'s format), so this is a second prescription of what a task spec holds, enumerating in prose the same four parts — including both members this task drops. After the edit the engine says a task spec holds "three parts and nothing else" while its principal caller, in the one mode dedicated to writing a task spec, still asks for `guards, how to verify`. That is an engine and its caller disagreeing about the artifact the engine defines, and CLAUDE.md § "Dependencies and the skill graph" makes the callers' expectations part of the engine's contract precisely for this case. It also runs against the phase's own thesis, since `how to verify` is the register 34.3 removes from the work-order.
   The repair *edit* is out of this task's file boundary (see Deferred observations); what is in boundary and must change is the plan's claim. Narrow it to what was actually verified — the literal enumeration occurs once, at `roadmap-engine:105` — and name the surviving prose restatement at `roadmap-decompose:88–89` as known and deliberately out of scope, so the implementer does not read the family as reconciled and the reviewer of the landing does not inherit a false all-clear. As written, the sentence asserts a state of the repository that a `grep` for the *concept* rather than the *string* disproves.
