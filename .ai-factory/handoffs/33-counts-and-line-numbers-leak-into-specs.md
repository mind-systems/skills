## 2. What was found

- **Line numbers.** The rule's home is the global `~/.claude/CLAUDE.md` § «Grounding claims» («A reference addresses by **name**, never by position»). `roadmap-outline-deep`'s own verbosity directive for the phase note permits the opposite: «a `file:line` where a claim needs one». Separately — not caused by that directive — Phase 64's task specs in `tradeoxy_core`, written through `roadmap-decompose`, carried twenty `(lines ~54-67)`-style citations that a gap-closing pass had to strip; no skill asked for them, the writer added them by habit, and the usual hygiene pattern `:[0-9]+\b` does not catch that form. The phase notes themselves carried none.
- **Counts.** A counts rule exists in two places only, both on the architect's side: `agent-architect/templates/buffer-seed.md`'s «Standing entry — the counts rule» («Keep a contract, delete a census… Date a measurement instead of asserting it as permanent»), and architect buffer `130` («прекрати уже считать!»). No other skill, no project rule, not the global instructions — the planner and reviewers never see it. And the seed's own escape hatch is the one that fired: «1 suite, 24 tests» *was* a dated measurement («Gate run on HEAD `65bc03e`»), and dating it did not stop the plan from copying the number as an expected value. Meanwhile `roadmap-engine`'s «What a task spec holds» asks for «what is true now, read from the code with exact values», and the architect's own habit of recording a gate as «1 suite, 24 tests» on the HEAD a spec was written against put a test count into spec `0255`. The plan copied it; task 64.4 landed first and added a case; the third plan review failed the plan on «24 → 25» — the only issue left open. Rescue report `rescue-reports/tradeoxy_core/0022-64-5-a-test-count-that-aged-under-a-neighbour.md`. The user: «опять эти сраные подсчёты протекли в спеку». The same count was stripped from the other open specs of that phase before it could fire again.

- **What the incidents have in common.** Every number that fired was a *measurement of the current tree* — how many tests a suite holds, which line a thing sits on, how many helpers or files a sweep reached, how many phases sit above — true at the moment it was taken and broken silently by the next neighbouring commit. None was a *decision* — a page limit of 200, a 500 ms race, a 400–1000 character budget — which stays true until someone changes it on purpose. So no list of forbidden counts is needed, only one question put to any number in an artifact: is it a decision or a measurement? A decision is written; for a measurement, what produces it is written — the suite's name, the symbol, the sweep command — and the number itself is left to whoever runs that when they need it.
