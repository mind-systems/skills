# OrderCloseFinalizer.finalize stamps closeDate, both close paths converge on one write — the snapshot seam the spec promised on a path that has none

**Project:** tradeoxy_broker
**Date:** 2026-09-19
**Stopped at:** escalated
**Elapsed before the rescue:** absent

The test task behind `.ai-factory/specs/0007-close-finalizer-closedate-stamp.md` exists to pin that `OrderCloseFinalizer.finalize(order:subscription:)` is the single site that stamps `order.closeDate`, and that both close paths converge on it rather than stamping the field themselves. Two of its cases cover the path through `CloseOrderManager.createTakeThrowing`: a take filling at `percent == 100` must reach the finalizer, and a take filling below it must not.

The spec's `## Instantiation` section tells the implementer to seed a staging subscription and inject an order-book snapshot "via the existing `StubOrderBookProvider: IOrderBookSnapshotProviding` pattern already used across the `StagingBroker*Tests.swift` files." That pattern works exactly where the provider arrives as a constructor parameter — `StagingBroker(orderBookProvider:)` takes one, and a test substitutes a stub there directly. `CloseOrderManager.createTakeThrowing` (`Sources/App/Managers/CloseOrderManager.swift`) takes no such parameter: it reaches `App.shared.brokerFactory` for its broker and `App.shared.orderBookProviderFactory` for its provider from inside the method body, and both properties are declared `let` on `App` (`Sources/App/Core/App.swift`), concrete types with no substitution point.

The chain closes completely rather than partially. `OrderBookProviderFactory.provider(exchange:marketType:symbol:)` always constructs a real `OrderBookProvider`, whose `snapshot` is `private(set)` and is written only by its own private `store(_:)`, itself fed from the live `watchOrderBook` stream against the core gRPC host and port. A `@testable import` reaches a type's internal members, not a `private(set)` property's setter, so nothing in a test can seed that value from outside the actor. With no core running, the snapshot stays `nil`, and `createTakeThrowing`'s `guard let currentPrice = order.direction == .long ? snapshot?.bestBid : snapshot?.bestAsk` throws `Abort` at code 414 — before the method ever reaches the `percent == 100` branch the two cases exist to distinguish. Both cases, the one that must stamp and the one that must not, die at the same guard, before either reaches the behavior under test.

This is the shape `.ai-factory/ROADMAP.md`'s `## Testability Seams` direction already names in its own words — the thing a test must vary is acquired inside the method from a fixed, unsubstitutable collaborator, never received as a parameter — and `.ai-factory/ROADMAP_TESTS.md`'s own header states the boundary a test task works inside: write correct interface-based tests without modifying production code. Reconciling the spec's instruction with the code as it stands would mean giving `CloseOrderManager` a seam it does not have, and that is a production-code decision, not a test-authoring one — outside what a test task, or the run executing it, holds the authority to make on its own.

The same false premise sits in a second file. `.ai-factory/specs/0008-preorderprice-capture-slippage.md`'s `## Instantiation` describes `CloseOrderManager`'s close-side capture as reachable through "same `StubOrderBookProvider` seam, but now via the DB harness" — the same manager, the same absent seam, the same dead end. The decision this run stopped on therefore governs two test plans, not the one it was working.

> The decision the run stopped on: narrow the task to the two cases that already have a path — the finalizer called directly, and the fill routed through `PositionToLocalOrderSyncManager`; add a substitution-seam task ahead of this one so `CloseOrderManager` receives its broker and order-book provider through an injected protocol, and gate this task on it; or stand up a fake core watcher service on an ephemeral port so the real provider fills from that instead of a live core.

## What was done

The decision was taken to prepare the code: a substitution seam on `CloseOrderManager`, to be written as a task in the main roadmap, with the test task gated on it. Because the decision belongs to that neighboring task rather than to this one, `0007` and its contract line were left untouched. The discarded plan and its sidecar were deleted, which also cleared the escalated state, so the task re-plans clean once the seam lands. No plan-review, review, or test-run file existed for this task — nothing else was removed.
