## The discipline relies on things it never writes down

Grounded in live incidents this session: after a compact the architect reported its editor dead and the user disproved it by hand, and a round was closed before the editor could speak at all. Each time the skill already held the intent — a coexisting buffer, a live editor, a reconcile step — and left the mechanism that would hold it to be inferred. An inference survives neither a compact nor haste. This direction writes the mechanisms down where the assertions already stand.

### Phase 26 — agent-architect states the mechanisms its own text assumes

`agent-architect/SKILL.md` asserts three things it never mechanizes: that a handoff carries the editor's handle and the buffer's path without ever saying whose handoff does, that a dead editor is "a stale handle discovered at recovery", and — by exposition order alone — that nothing is released before the editor's report. So the buffer's path travels only when the architect happens to think of it, the liveness test was filled in by the architect itself with the one tool that cannot answer it, and a relay and its work-order can leave in one message with the rule intact. The first three tasks run in file order: the pairing roles between two architects are named first, since the state task that follows only gains a role to record once the roles themselves exist, then the architect's own state — the editor's handle, the buffer's path, and any assigned role — is written where a compact cannot reach it, and last the release order becomes a stated invariant. A fourth follows them, one file over: the pairing skill 26.4 produces tells its applying half to apply a work-order the way an editor would, and leaves the check that phrase stands for in a file that half never loads.
