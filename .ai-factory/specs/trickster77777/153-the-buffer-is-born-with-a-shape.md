# Phase 59 — the buffer is born with a shape

Governing spec: `docs/paired-loop.md`

`src/skills/architect-editor-engine/SKILL.md` § "The architect's buffer" still defines the buffer as split into two zones — settled and live — with what each zone holds in general terms. The user has since ruled the split out entirely: the buffer has no zones and no region the editor may not read; the head is the memory's only writer, and the hand reads it in full and never writes to it. `docs/paired-loop.md` § "What the memory holds, and who holds it" already states this. `src/skills/agent-architect/SKILL.md` § "Spawn once, message thereafter" is where a buffer is actually created — "no such pointer means you are a new architect and create your own buffer first, at the path and numbering the engine defines" — and `src/agents/editor.md` carries the same zone vocabulary, inherited from the engine both halves load. Independent of the zone question, neither file states what a new buffer's *content* is at the moment of creation — nothing seeds it with a starting shape. `.ai-factory/handoffs/29-the-architects-snapshot-is-a-history-not-a-telegram.md` names the consequence directly: "the pair reinvents the buffer's shape at every founding and the shape it converges on is always the same" — a where-things-stand paragraph, rulings in force, method, orientation, a ledger, rescues, candidates — not tasks, and the architect's own current thread, an open question still being read. A shape that converges independently every time is knowable and currently unwritten.

The need is once-only, at an architect's birth; a buffer that already exists is merely resumed, per the governing spec's own lifecycle ("A head that begins from such a snapshot works in the buffer it names... A head that begins with no such pointer is a new head: it creates its own buffer first"). A template loaded every session for a once-only need violates the family's own cost rule, stated in `docs/sakshi-harness/skill-graph.md`: "В пространстве скилов каждая загруженная строка — постоянная стоимость в контексте" — every loaded line is a recurring context cost in this family, paid on every turn the skill stays in context, regardless of whether that line does anything on this particular call. `architect-editor-engine` is loaded by **both** halves on **every** session — its own text: "Load this skill once at birth — the architect per the instruction in its own body, the editor as the first action on spawn." A seed template living there would be paid twice, every session, including the overwhelming majority where the buffer already exists and the template is never read. And the editor never creates a buffer at all — nowhere in `agent-architect`'s "Spawn once" section does buffer creation belong to any hand but the architect's own — so the engine, loaded equally by a party that will never use the template, is doubly the wrong home.

A skill directory already admits the mechanism this needs: `CLAUDE.md`'s "Each skill directory contains" enumeration lists `templates/` — "optional — output templates" — alongside `references/` and `scripts/`, read once at the moment a skill needs it rather than held resident every session. This is not a hypothetical mechanism: `src/skills/aif-docs/templates/html-template.html` is a real instance of it on disk, cited only from `references/html-generation.md` ("Read the HTML template from `templates/html-template.html` and use it for each page"), itself read only "when `--web` is passed" — a per-invocation file, resident in no session's context until the specific call that needs it, exactly the shape a once-only buffer-seed template wants.

What the template seeds, drawn from handoff 29's own naming but flattened per the ruling into one set of rubrics, not two: *where things stand* (rewritten each time, never appended), *rulings in force*, *method*, *orientation*, a *ledger*, *candidates — not tasks* (each with the trigger that would promote it), and a *current thread* — the architect's own read of an open question, a diagnosis still forming, now as readable to the hand as everything else in the memory. Handoff 29 also named a *rescues* rubric; it drops here, by the user's own ruling that a rescue's own report already exists on disk and `task-rescue` owns it — leaving seven. The handle and any pairing role sit where `architect-editor-engine` already puts them and need no duplicate slot in the template.

The template is seeded with standing entries, not left empty, and the first of them is the counts rule. `docs/counts-go-stale.md` § "Why this is written down here" records that the distinction "was derived independently in three architects' private buffers, in three different projects, each time after a human asked for it, and each version drifted from the others — because a buffer is by design not read by any other architect." Handoff 29 names the same failure by its general shape, already documented in `docs/instruction-in-data.md`: "an obligation with no procedural home does not execute" — there, the `Processed:` mark, unset in eighteen of twenty recent handoffs because the instruction to flip it lives only inside the file it governs rather than in a step that touches the file; here, the counts rule, re-derived by hand three times because no artifact carried it forward from one founding to the next. The entry is not a pointer to `docs/counts-go-stale.md`: that file exists only in this repository, while the buffer lives in whatever project the pair works in, and a pointer there resolves to nothing once the buffer travels. So the entry carries the rule in its own words — keep a contract, delete a census, date a measurement; a number stays only where the sentence would still read true after someone adds a member without touching it; two counts that disagree are not reconciled, ask which member is missing. The template travels with the skill, and is therefore the only carrier that reaches a project where these documents do not exist — that is the reason it holds the text rather than a reference; `docs/counts-go-stale.md` stays the rule's first home, the template its second, seeded rather than rediscovered, and a skill step that writes durable artifacts naming it — where `instruction-in-data.md`'s own check would place the obligation — its third.

The boundary the template must hold: it *instantiates* the memory — fills it with its starting shape at birth — while `architect-editor-engine` keeps what the memory is and who writes it, independent of any one buffer's current content. The template names no zone and draws no boundary of its own; one fact stays in one home.

This partially bridges what note `143-the-container-is-per-head-and-the-content-is-not.md` calls the missing continuation mechanism between per-head containers: a seeded template gives a newly founded buffer the same starting shape a departed head's buffer had, rather than leaving project-scoped discipline to be re-derived from nothing at every founding. It does not answer phase 49's own fork — whether the buffer is a staging area the drain rule already covers, or the project's durable memory needing a continuation mechanism the spec does not yet have — which stays with the user.

Nothing under `docs/` is written.
