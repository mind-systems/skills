# The memory snapshot is written on request

## Current state (grounded, read fresh)

`src/skills/agent-architect/SKILL.md` names exactly one occasion for a memory snapshot, in the opening of its handoff sentence: "Before a compact, the handoff continuing this same architect across it". Nothing else in the file — not at spawn, not at pairing-role assignment, not anywhere else — names a second occasion; a compact is the only trigger the skill states today.

The same sentence closes by naming what the digest of the editor's accumulated state is for and who it stays with: "the digest is your own recovery note and is never sent to the editor" — true today, and untouched by this task.

## The change

The occasion widens: alongside the existing trigger, the architect writes a memory snapshot whenever the user asks for one, mid-session — its own capability, reached by a request rather than by a command, no command invoked and no template consulted. What it carries stays as already settled: only the volatile residue — where the work stands, what the hand knows, what will slip first, and what must not be resolved by inference — because everything durable already lives outside the conversation, never an inventory of the session. Each new snapshot supersedes the last by name, so a reader never follows a stale next action.

A second site in the same file names the occasion rather than the artifact: § "On every invocation" closes by rebuilding working state from "the pre-compact handoff that recorded your buffer's path" — true only while a compact is the sole occasion. This task rewords that sentence so it names the artifact rather than the occasion, so an on-request snapshot recovers the architect exactly as a pre-compact one does.
