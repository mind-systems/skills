# Phase 43 — the gap pass walks every task alone and reports once at the end

The user asks the gap pass over every open task individually and types the same instruction each time: "по открытым таскам. По одному. Не останавливайся, пока не закончишь. Отчёт в конце. Если блокеры будут — тоже в конце будем решать." His ruling: "Я бы изменил этот скилл так, что б он всегда работал с одним таском." No document states the unit of the pass; a skill is its own documentation, so none is written.

What diverges is in `src/commands/command-pin-gaps.md`, which holds the unit fixed in its questions and open in its targeting.

- **The targeting paragraph.** It names the target as "the scope under discussion in chat (a named task, phase, or task spec)" or "all open `- [ ]` tasks of the roadmap in play … above `---STOP---`, scanning each contract line and its `Spec:`-tagged task spec". It accepts many tasks in one invocation and does not say whether the walk repeats per task or runs once over all of them.
- **The unit paragraph and the deciding question.** "The unit of the walk is one behavior the task claims", and a finding is decided by "would the run, holding this task and nothing else, have to invent". The condition is true only when one task is held; several held in one reading remove it, and a hole that one task's context closes goes unseen. The walk's answer looks as confident as under the true condition.
- **The report.** The default mode says "edit the file in place" and then "report `N closed from source · M blocking · K owned elsewhere`". The file is singular and the line is one report, and nothing says what happens between tasks, whether the pass stops, or where the blockers of several tasks are gathered for the user, who decides them at the end.
- **A second mode.** Beside the default, the command keeps a scan mode, triggered by `scan`, `report` or `только скан`, that lists findings as `[file:line|spec-location] → …` and stops, with nothing said of many tasks, and its frontmatter description and argument hint advertise it. The user does not use it: "Режим один — проходим тот диапазон, который я указал. Других нет." The command comes to have one mode and no label for it.

What no longer diverges, or leaves the phase. The `skill-cycle.md` account of the pass, § "Пины — `command-pin-gaps`", is singular throughout, names no phase or batch, and counts the same three groups the report line holds, so the code and the doc do not disagree. The empty-result half of the phase is dropped: no field case shows a clean pass being padded, and the skeleton's remark that most tasks pass through untouched is no longer in the file.
