# Phase 81 — a task carries its source, and a find without one goes to the user

[what-a-task-carries](../../../docs/what-a-task-carries.md) § "A task has a source" says a task "answers to something: a document's promise, the user's ruling, or the path to a goal the user set", that "A find that has none of these is real and still not a task. It goes to the user", and that "A template constant that names a source records nothing, while an absent field at least prompts someone to ask". [principles-at-their-moment](../../../docs/philosophy/principles-at-their-moment.md) names it among the questions asked where a decision is made: "`what-a-task-carries` asks of every task, when it is about to be written, what it answers to". The skills do not ask it, and the field a template offers answers it with a constant.

Where the files stand:
- **`note`** (`src/skills/note/SKILL.md`): the default template, under "Note file template", opens with `**Date:**` and `**Source:** conversation context`, and Step 1, "Analyze Context", has it "Review the full conversation" for what to mine. A spec composed through it takes whatever the conversation held, whether the task asked for it or not.
- **`roadmap-engine`**, § "The two-tier artifact": the task spec "follows `note`'s format", and the engine passes `note` a destination alone, "via `note`'s destination hook"; its "What a task spec holds" defines three parts and sets no template. So a decompose run gets `note`'s default template, Source line included, with the three parts in the body.
- **`roadmap-decompose`** has no step that asks a task's source; the Atomicity Gate, hook (b), is the one question it puts to each entry before its contract line.
- **The field in use.** In the projects that use the family, specs written this way open with the title, a `**Date:**` line and a `**Source:**` line. Most values name the writing skill — "roadmap-decompose", "roadmap-outline-deep", "roadmap-test-coverage agent" — or a place in the plan layer — "ROADMAP.md Phase …", a roadmap section with its phase and task, a phase-note path. Some name a handoff, a document section or a ruling; some a "code-drift finding" or "conversation context — " and a planning session's name; and the recent specs of one project carry no field at all. A skill's name or a plan location records who wrote the task or where it is listed, not what it answers to: the field that only looks answered. The specs on disk in this repository carry no such field.

The phase is for this: a task answers to something the system asked for, and the skills ask that at the moment a task is written.
