# Paired-loop channel protocol becomes a resident engine both entities load

Handoffs 02 and 03 (this session) caught the architect↔editor channel drifting from how the loop is actually run. The user's `::` model is a mid-message split, not a trailing-only marker; a relay's skill-expansion reading "apply" misreads a research pass as an edit order; and the editor has no report-only default, so a relayed skill with its own write-capable default can promote a round to edit-mode without the architect ever authorizing it (hit once live, per handoff 03 §3). A first pass proposed fixing this with a shared doc as the one home for the contract; **rejected** — the architect and editor get instantiated in other projects where this repo's `docs/`, root CLAUDE.md, and `reserved-words.md` are all absent, so a doc cannot travel with the pair the way the pair itself does. The fix instead extracts the shared output contract into a new, thin global engine skill that both entities load at their own birth — the architect at session start via its own `loads:` frontmatter edge, the editor as the first action on spawn via a body instruction — exactly as `roadmap-decompose` loads `roadmap-engine` at the start of its run. Loading at birth, not lazily per message, is what makes the contract resident the moment a channel-message arrives, which a lazily-invoked skill or a doc pointer cannot guarantee.

`::` parsing itself stays entirely inside `agent-architect/SKILL.md` — the editor never sees a raw `::`; it only ever receives one of the engine's two channel-message formats. The engine therefore carries zero `::` grammar and zero policy about when to use which format; it is a pure output-contract description, the same shape as `test-philosophy` or `roadmap-engine`'s format section.

## The change — four artifacts, one atomic task

1. **New `src/skills/architect-editor-engine/SKILL.md`.** Frontmatter: `name: architect-editor-engine`; a `description:` stating it is the shared channel-message format contract for the architect↔editor pair; `user-invocable: false`; `disable-model-invocation: false` (engine baseline — never `true`, this is not a user-facing skill); minimal `allowed-tools: Read`; **no `loads:`** of its own — it is a leaf engine with no callees. Body, thin and self-describing, holding only:
   - The **REPORT-ONLY** format: a research relay — the receiver reads/runs the named target, reasons independently, reports by fact, and writes no files. Used for every relayed analysis target and every relayed skill-expansion.
   - The **APPLY-EDIT** format: the pinned apply work-order — exact edits, guardrails (what not to touch, a collision-safe method where order matters), the commands to self-verify, and an explicit do-not-commit. Used only for the architect's own authored, confirmed change.
   - The mode rule: a receiver keys its mode strictly off **the format token that literally opens the message** (`REPORT-ONLY` / `APPLY-EDIT`) — never off content, never off a referenced skill's own default behavior. Ambiguity (no recognizable token) resolves to REPORT-ONLY.
   - Nothing about `::` — the engine has no opinion on how the architect parses raw user input; that stays entirely with its caller.
   - The standard load-once + reverse-graph marker paragraph, this one's grep line naming **both** `src/skills/*/SKILL.md` **and** `src/agents/*.md` — the one engine in the family with an agent caller: `` grep -l "architect-editor-engine" src/skills/*/SKILL.md src/commands/*.md src/agents/*.md ``.
2. **`src/skills/agent-architect/SKILL.md`** — add `loads: architect-editor-engine` to frontmatter; add an instruction to ensure the engine is loaded once this session (via the Skill tool, only if not already loaded), alongside the existing spawn-once discipline. Rewrite the `::` grammar in place: the marker never *opens* the message (a leading slash-command is preserved exactly as today) but may trail **or split mid-message**; everything before the mark is the payload, worked by **both** the architect and the editor in parallel, then reconciled — the architect performs its own part, not a mere relay; everything after the mark is for the architect alone, and the enrich pattern is named there (the architect enriches the before-mark payload with named context from its own chat before sending it on). The relay-expansion transformation (today's `"apply it with arguments"` skill-expansion) is rewritten to emit a REPORT-ONLY-formatted message instead — "read and run `<SKILL.md>` with arguments … as a report; write no files." The existing "author your own prompt in exactly one case" section is reframed as authoring an APPLY-EDIT-formatted message. The `## Review in parallel, reconcile before the apply order` section is reframed as an explicit special case of the general before-mark-both-entities rule — its own review-specific discipline (adversarial, name the specific plantable failure, hunt propagation gaps, concede/hold on reconciliation) is kept, not diluted.
3. **`src/agents/editor.md`** — add a body instruction (not a frontmatter `loads:` — agents carry no such field) directing the editor to load `architect-editor-engine` via the Skill tool as the very first action on spawn, before processing the first channel-message. Rewrite the opening mode-tell paragraph (today's L18–22) to key strictly off which of the engine's two format tokens opened the message, replacing the current "tell which by what arrived" content-based framing. Add the hard report-only default under the pinned-skill-path paragraph (today's L43–48): a pinned skill's own write-capable default never by itself promotes a round to APPLY-EDIT — only an explicit REPORT-ONLY vs. APPLY-EDIT token on the message decides mode, and any ambiguity defaults to REPORT-ONLY, full stop, the same way auth-ambiguity already defaults to no-authorization elsewhere in this file.
4. **New symlink `active/skills/architect-editor-engine` → `../../src/skills/architect-editor-engine`** — without it neither caller can resolve the skill via the Skill tool; the engine is otherwise invisible to the harness.

## Design decisions resolved (do not re-litigate)

- **Format signalling is hard, not advisory.** Every channel-message the architect sends the editor literally *opens* with its format token (`REPORT-ONLY` or `APPLY-EDIT`) — this is a byte-exact protocol token in both files' operative text, on the same axis as `PLAN_REVIEW_PASS` / `## Deferred observations`, not prose to be paraphrased.
- **The engine holds zero `::` grammar.** `::` parsing is entirely `agent-architect`'s own concern; the engine only ever sees/produces the two format tokens.
- **The "Review in parallel" section folds in as a special case** of the general before-mark-both-entities rule — decided, not deferred to a later task.
- **No shared doc; 22.1 makes no `reserved-words.md` / root CLAUDE.md / `docs/` edit.** The protocol vocabulary is isolated to the pair, so its `relay` / `channel-message` / `work-order` entries were removed from `reserved-words.md`'s `## Paired loop` section as a separate planning edit (they name mechanism internal to the pair, not shared registry vocabulary); 22.1's own implementation touches none of these files.

## Guards

- `reserved-words.md`, root CLAUDE.md, and everything under `docs/` are untouched by this task.
- The apply-work-order authoring mechanics in `agent-architect/SKILL.md` (pin every value/path/guardrail, self-verify commands, explicit do-not-commit) and its "Verify the editor's report by fact" section stay behavior-identical apart from being framed as producing/consuming an APPLY-EDIT-formatted message.
- The engine's own frontmatter stays at the engine baseline — `user-invocable: false`, `disable-model-invocation: false` — never `true`; it is never meant to be user-invoked directly.
- Preserve register in both edited files — targeted rewrites of the existing voice, not a wholesale rewrite of either file.
