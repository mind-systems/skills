# The buffer's definition moves into the engine both halves load

## Current state (grounded, read fresh)

`src/skills/agent-architect/SKILL.md` states the buffer's privacy in two places, not one, and the first of those places shares its sentence with a third claim that is not about privacy at all. § "Your buffer is yours alone" defines the buffer — its content, its path, its numbering — and states, in one sentence, three things: that the editor is never told about it and no work-order references it, that nothing is broken if it happens to see the file, and that it is the one file the architect edits directly, because it isn't a shared artifact. The first two close the buffer to the editor by name; the third names who writes the file and gives its own reason. Elsewhere in the same file, § "Spawn once, message thereafter" states the same privacy claim — not the direct-edit one — as a parenthetical justification for a different rule: "no other handoff has any reason to mention the buffer or the handle, since nothing outside this skill ever learns about either".

Both callers of `architect-editor-engine` name it narrowly. `agent-architect` calls it "the shared channel-message-format contract" and gives loading it early one reason: "the contract must be resident before a `REPORT-ONLY` or `APPLY-EDIT` message is ever composed." `editor.md` carries the same appositive and the same single reason: "it is the shared channel-message-format contract for this pair and must be resident before you read anything sent to you." `architect-editor-engine`'s own `description:` field states "Holds only the two formats; when-to-use policy stays with the caller.", and its body carries exactly two sections — "## The two channel-message formats" and "## The mode rule" — no buffer, no mention of shared memory. `docs/paired-loop.md`'s own opening context already names this file as the buffer's home: "Its shape and rules live in the engine both halves load at birth."

No settled/live split exists anywhere in `agent-architect`, `editor.md`, `architect-editor-engine`, or `architect-pairing-engine`. The buffer's only stated content, per `agent-architect`, is deferral entries: "Each deferral entry names *what*, *why deferred*, and the *trigger* that resolves it... deferral entries remain the buffer's primary content." The same section — "Your buffer is yours alone" — also records the editor's handle and any pairing role the user has assigned for the session.

`.ai-factory/ARCHITECTURE.md` § "Composition: mechanism vs policy" gates a move into a shared skill on carrying "shared content — a mechanism, rule, or format used by two or more callers." Both halves already load `architect-editor-engine` at birth — `agent-architect` before that first channel-message, `editor.md` as the very first action on spawn — and under `docs/paired-loop.md`'s model the settled zone is exactly that: content both hold. Nothing in the mechanism/policy rule blocks the move; its own test argues for it.

## The change

`architect-editor-engine` gains the buffer's definition: where it lives — naming the engine as the explicit home of the buffer's path and its numbering, not left implicit, since the sentence currently stating this in `agent-architect` is the one being cut — the two zones and what each holds, which zone the editor holds as its own working context and why the live zone stays with the architect alone, that the editor re-reads the settled zone on change rather than once at birth, and the drain rule. Its own `description:` and every place it names itself stop claiming it holds only the two channel-message formats.

`agent-architect` stops defining the buffer itself and points at the engine instead, naming it as the home of the buffer's path and numbering — a pointer, not a restatement of the zones, the drain rule, or the re-read rule the engine now holds. The sentence quoted above, in § "Your buffer is yours alone," carries three clauses, and they do not share one fate. Both privacy clauses go: "the editor is never told about it and no work-order references it" and "nothing is broken if it happens to see the file" are false after this task, since the editor holds the settled zone by design rather than stumbling on it by accident. The third clause survives — "it is the one file you edit directly" stays, the architect's one direct-write exception to "you never touch the shared artifacts." Its stated reason does not survive with it: "because it isn't a shared artifact" stops being true once the settled zone is read by both. The reason that replaces it is narrower and still holds — the architect is the buffer's only writer. At the second site — the handoff parenthetical in § "Spawn once, message thereafter" — what survives is the rule it actually carries, narrowed to what still holds — no *other* handoff has reason to mention the buffer or the handle — with the "nothing outside this skill ever learns about either" justification dropped, since the editor now learns about the buffer's settled zone by design.

The boundary with 36.2 is the creation-moment sentence alone — "At the moment you spawn the editor..." — not the section it sits in. Nothing else in § "Spawn once, message thereafter" is fenced off by that boundary — in particular the appositive naming the engine and its load-reason are in scope for this task, not 36.2's.

Both callers' appositives are in scope, because both go stale in the same way once the engine stops being only a channel-message contract: `agent-architect`'s appositive and `editor.md`'s each stop calling the engine the channel-message contract alone, and each load-reason widens to cover the buffer's rules as well as the message formats — the editor holds the settled zone from birth, which no arriving message triggers. `editor.md` joins this task's file set for this one clause. The widened clause must cover the buffer's rules, so `editor.md` names the buffer in the same word the engine uses; the file gains no path and no recovery account — those stay outside this task's one clause.

`agent-architect` goes on naming what the architect records there — the editor's handle, any assigned pairing role, and its deferral entries — and labels none of them with a zone; the engine states what each zone holds, and the architect loads that engine at birth.

## Blast radius

Both halves already load the engine at birth, so the definition reaches the editor through an edge that already exists — no new `loads:` entry anywhere. `editor.md` is edited for the one appositive-and-load-reason clause above; nothing else in that file changes, and it gains no new section and no new rule.

The handoff sentence in § "Spawn once, message thereafter" reads "records your buffer's path (below)" — the "(below)" resolves into the section this task strips the path from, so left unworded it would point a reader at a pointer rather than a path, one hop short of what it promises. This task rewords that reference so it stays true.

The buffer files already on disk are not rewritten; only the skill text defining the buffer's shape moves.
