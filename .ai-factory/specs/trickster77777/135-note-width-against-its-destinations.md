# Phase 41 — the width is fixed where the folders are not

`note` § "Save Note to File" fixes the written width unconditionally — "`<NN>` is a zero-padded four-digit sequence number (`0001`, `0002`, `0003` …); this width governs only what `note` writes — existing names of any width are still read" — while § "Hooks (caller inputs)" defines the numbering scan that reads that same leading run "as an integer, comparing numerically rather than as a string." The padding therefore serves nothing the mechanism itself reads: lexical order is not what it sorts by, and the `9999` bound rests on its own explicit check — "When the highest number the scan finds is `9999` or greater, `note` writes nothing" — not on the width at all. Bound and padding separate cleanly, and only the padding collides; that is the finding that decides how narrow the repair is — the scan and the bound stay exactly as written, and only the four-digit literal moves.

Every destination the reverse graph resolves to is unpadded. `.ai-factory/specs/trickster77777/` runs two digits into three as it grows past ninety-nine, unpadded both sides; `.ai-factory/handoffs/` and each project's `.ai-factory/rescue-reports/<project>/` are two digits throughout. The one that matters most is `note`'s own unhooked default, `.ai-factory/notes/`: an invocation that supplies no destination hook at all lands in the same two-digit folder this repository's own architect buffers already occupy, so the collision sits in the mechanism's default branch, not only at a caller's chosen destination. `tradeoxy_core` carries the identical shape in both its spec directory and its handoff directory — the same two-widths-growing-unpadded pattern, not a special case. None of this is stated as a high-water number: a number naming the top of a directory that gains a file on every run is false the moment it does, which is why the preamble's own `138-` is already stale against the live folder.

`note` already holds the principle its own repair needs, and already exempts the one thing that collides. Its folder-style step reads the destination's most recent siblings to match "the folder's prevailing register," stated as "matched, never content-copied" — applied today to prose density and heading habits, never to the filename, which is the most visible thing a folder's style actually decides. The repair this phase points toward is not a new mechanism but the same matching rule reaching one more property it currently skips.

`roadmap-outline-deep` § "Re-run rule" gates its direct-write branch on a `Phase note:` pointer already existing in the phase's own preamble — it only ever rewrites a note already on disk. For a phase with no pointer yet, the whole instruction is "Invoke `note` only for a phase that has no pointer yet," and following it literally mints a four-digit name into a folder that has never carried one. The rule has now been obeyed by going around the mechanism twice: once in `tradeoxy_core`, where the field report this phase is drafted from recorded the same workaround, and once in this run — this very note, `135-note-width-against-its-destinations.md`, was written directly rather than through `note`, for the identical reason.

The blast radius runs wider than `note` itself, in two different ways. `roadmap-test-coverage` does not load `note` at all and carries an independent copy of the identical rule, word for word — "this width governs only what this skill writes; existing names of any width are still read" — so a repair to `note` alone leaves a second, unconnected carrier of the same defect standing. `agent-architect` writes a memory snapshot into `.ai-factory/handoffs/` by the architect's own hand, declares no `loads: note`, and states nowhere in its own text where that file's number comes from — a third carrier, not duplicated but undefined.

No document under `docs/`, in `CLAUDE.md`, or in `.ai-factory/ARCHITECTURE.md` describes how a number is chosen or a note is placed. Under the standing ruling that a single skill's behaviour belongs in the skill, none would ordinarily be owed for this. But the behaviour now sits in three places — `note`'s own mechanism, `roadmap-test-coverage`'s independent copy, and `agent-architect`'s undefined third — and whether one skill's own documentation still covers a rule three carriers hold between them is the open question this phase leaves for whoever decomposes it.
