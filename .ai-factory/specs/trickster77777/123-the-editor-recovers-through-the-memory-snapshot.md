# The memory snapshot is written on request and reaches the editor

## Current state (grounded, read fresh)

`src/skills/agent-architect/SKILL.md` states a direct contradiction with the governing section. Its spawn-once paragraph opens by naming the one occasion it recognizes for a memory snapshot — "Before a compact, the handoff continuing this same architect across it" — and reads on: "records your buffer's path (below) and a digest of what the editor has accumulated; the digest is your own recovery note and is never sent to the editor." Nothing else in the file names another occasion; a compact is the only trigger the skill states. The clause is explicit and absolute: whatever the architect gathers about the editor's own accumulated state stays with the architect.

`docs/paired-loop.md` § "How the memory begins, and how it survives" states the opposite as governing behaviour: "A hand's own history ends without a signal. Nothing announces the loss, and a hand asked to recall what it no longer carries answers anyway, confident rather than true. What recovers it is the head's latest memory snapshot, handed to it again — the same artifact that carries the head across a break carries the hand across its own." The same artifact the skill says is never sent to the editor is, in the governing section, exactly what recovers the editor.

`src/agents/editor.md` says nothing about its own context ending. Its one passage nearest the subject reads: "You carry history across rounds — what's been done, where past rounds went wrong — and it sharpens you; you're expected to notice what the architect missed. But never depend on it: every round is self-contained by contract, and a fresh editor picking up from the next round alone must succeed just the same." This anticipates a "fresh editor" continuing but states nothing about how that transition is noticed, what signals it, or what a fresh editor is handed to recover from the loss — the file carries no recovery mechanism of its own.

## The change

`agent-architect` must state instead that the memory snapshot carrying the architect across a compact carries the editor across its own: whenever the architect itself rehydrates from a memory snapshot, it hands that same snapshot to the editor — unconditionally, since no one can evaluate whether the editor's own history has run out, and handing it over costs less than establishing that. The digest of what the editor has accumulated is one part of that snapshot — the part that speaks to the hand's own lost history, exactly as the buffer's path is the part that locates the shared memory — so the reason the "never sent to the editor" clause goes is visible: it withheld one part of an artifact that now travels whole. The clause is removed, not softened; it is precisely the claim the governing section overrides.

`editor.md` gains what it lacks today: a statement that its own context can end with no signal, that recovery is not something it detects or requests, and that the architect hands it the latest memory snapshot whenever the architect itself rehydrates from one — unconditionally, whether or not this editor's own history actually ran out — consistent with the governing section's own account of the hand's side of the exchange.

`agent-architect` gains a second occasion: writing a memory snapshot whenever the user asks for one, mid-session, not only ahead of a compact — its own capability, reached by a request rather than by a command, no command invoked and no template consulted. What it carries is only the volatile residue — where the work stands, what the hand knows, what will slip first, and what must not be resolved by inference — because everything durable already lives outside the conversation: the roadmap holds time, the specs hold decisions, the buffer holds the practice. Written as an inventory of the session it is neither short nor a snapshot. Each one supersedes the last by name, so a reader never follows a stale next action.
