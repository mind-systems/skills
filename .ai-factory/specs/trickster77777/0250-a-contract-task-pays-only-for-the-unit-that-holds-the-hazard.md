# Phase 90 — a contract-task pays only for the unit that holds the hazard

[names-and-reasons-not-laws](../../../docs/names-and-reasons-not-laws.md) governs the form: what the skill carries is a reason the agent lacks, never a rule written ahead of the case.

`roadmap-decompose-skeleton` splits a contract-task off a heavy task that touches two of its three hazard classes: async I/O, a stateful buffer, a lifecycle. Its "Lens 3 — Concurrency" defines the contract-task as the invariant plus test scenarios per concurrent caller, with no production code, ahead of the implementation task; § "Step 2: Order and fuse" fuses a skeleton and its red specs into one task when the skeleton and the implementation are one to one. So the contract-task a decomposer gets is a shell and a red suite. The lens triggers on the task, a whole surface, while the hazard lives in one unit of it. In the field the contract-task was cut over the whole mixed surface.

The reason the agent lacks: a red suite is written against a shell that throws, so none of its assertions has ever run. Whether it covers the wrong implementations of the next task can be judged only by imagining them, and imagination has no floor: each review imagines another wrong implementation that would pass. A unit without the lifecycle hazard has no need of that: it is built with its tests, and a test that runs has a floor. So a contract-task pays only for the unit where the lifecycle hazard lives, and the rest of the surface is built with its tests. The user, on the formulation: «у воображения — нету дна. Очень интересная формулировка.»

Two refinements the field has added, by core 130's message of 2026-10-20, which is in no file here. A task's tests and the body they test stay in one task: a review of tests alone judges them by imagining wrong implementations, and with the body in the same task the reviewer checks each assertion against the implementation. A contract is laid as late as possible: a contract suite landed ahead of its body goes stale when the model moves before the body lands, and every later plan then pays for rewriting the suite.

The phase is decomposed into 90.1: the lens fires on the unit that holds the hazard, with the reason above, and the two refinements stay cases here. The user: «давай декомпозить»; and on the lens's neighbour, «скелет просит делать через тдд. Где это валидно. И так и должно оставаться.» Touches keep collecting below.

**Cases.** Touches collect here, each as the root in a line and the form the repair took. The first two come from core 130's message of 2026-10-15, which is in no file here; there is no rescue report for them, because the rescue's scope-overload exit writes none. The later ones have rescue reports, and the cases that go with them are in phase 80's note.
- **90.6.1, the second clock's red contract.** The task stopped twice, and across the plan reviews no finding recurred: each round imagined a new wrong implementation of the next task that would pass the suite. In the first stop the scenario was a resubscribe over a pending seed; in the second it was trades in grace, a seed landing after a trade, and a bar emitted under the wrong symbol. The suite had been written against a throwing shell, so none of its assertions had ever run. The shell and the suite covered a synchronous store, a near-stateless source and the async clock, and only the clock carries the lifecycle hazard. The user: «мы нашли бездонный блэкбокс… Это не первый случай». Form: a split into tasks, at the user's pick and through core 123's razor. The store, a market-type function and the source are built with their tests; only the clock keeps a shell and a red suite, driven through the real units beside it. Every scenario the reviews found moved into the spec of the unit that owns it.
- **90.7.1, the minute contract.** The same shape: a synchronous assembler inside a red contract. Form: a split into the assembler, built with its tests, and the minute feed's contract.
- **93.17.1, the page judged by the clock** (rescue report `0041`). A catch-up unit filled a throwing shell under a rule whose model had already moved once, and the suite landed ahead of it was partly rewritten again; the report names half a suite rewritten among the behaviours the unit carried. Form: a split into a plain reader, with its own spec, and the catch-up runs; the report does not say which of the three hazard classes the runs carry. The report records the repair and not the contract's lateness; that reading is 130's message above.
- **93.17.1.2, the suite, not the body** (rescue report `0042`). The runs task, whose findings were all in the rewrite of the existing red suite: assertions and fixtures that pass without proving what they name, with the algorithm unquestioned and the severity falling to Low. Core 130's first move was to split the task into reshaping the red suite and filling the body; his hand showed the split to be a trap, and the report records it considered and rejected. The user: «Не то что бы прям находка, но хочу, что б скилы держали это в голове.» Form: spec plus plan depth, the body and its tests kept in one task.

After the first stop, the rescue repaired at spec and plan depth and read the rounds as a specification gap; that is the rescue report `0037` in [phase 80's note](0226-a-rescue-repairs-to-the-root-and-the-root-may-be-something-to-remove.md). The shape signal was a new finding each round with no fall in severity, which is the question that note asks, "Does the same finding recur, or is it a new one each round while severity falls?"

New touches are added as they come.
