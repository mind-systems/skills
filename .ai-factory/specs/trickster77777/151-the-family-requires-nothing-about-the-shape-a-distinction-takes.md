# Phase 57 — the family requires nothing about the shape a distinction takes, and is built entirely on that shape

No governing document exists for this phase.

Every appearance of the object-oriented vocabulary — polymorphism, subclass, encapsulation, dependency injection, strategy — in this corpus describes the architecture of our own skill system, and none of it is a requirement on the code the system plans. That is the claim worth holding, because it survives what a tally cannot: add a fourth genuine occurrence tomorrow and the claim still reads true — `docs/counts-go-stale.md`'s own test, applied to this note's own writing. Measured on this date: the vocabulary occurs as a genuine reference three times, across two documents. `docs/sakshi-harness/skill-graph.md`: "разделение — классическое separation of mechanism and policy (микроядерная архитектура); способ, которым философия выбирает поведение и отдаёт исполнение engine, — Strategy pattern." `.ai-factory/ARCHITECTURE.md` § "Composition: mechanism vs policy," twice: "mirroring the classic separation of mechanism and policy," and "the way a strategy varies independently of the context that runs it." The trap sits in two places at once: one vocabulary describing two different subjects, easy to conflate; and a second document, `.ai-factory/ARCHITECTURE.md`, sitting outside `docs/` while holding the same kind of claim, easy for a scan scoped to `docs/` and the skill bodies to pass over. A raw grep across `docs/`, every `SKILL.md`/command body, and `.ai-factory/ARCHITECTURE.md` returns five lines; the other two are false positives — a code comment in `roadmap-prune` ("`# Strategy: look at diffs on ROADMAP.md...`") and `roadmap-test-coverage`'s description field ("no prior test strategy"), both the ordinary English word, not the pattern. `docs/reserved-words.md` holds **41** registry entries (counted directly: 41 `- **term**` bullets), and none of them is about whether a kind is carried by a type or by a field.

Meanwhile the family is built entirely on injected-policy shape. `note` takes destination, template, and verbosity from its caller instead of branching on who called it — three named hooks, caller-supplied, all defaulting to today's standalone behaviour when unset. `roadmap-engine`'s maintenance flow takes granularity, the per-entry gate, target-file routing, and extra update-mode actions the same way — four named hook points, "the engine holds no opinion here." `roadmap-decompose-skeleton` and `roadmap-test-coverage` both load `test-philosophy` for its one discriminator rather than re-deriving loud/silent per caller. So the agent has been following the written discipline faithfully — the discipline just never asked whether a distinction's *shape* (type vs. field, subclass vs. branch) is itself governed. The repair is therefore **additive, not corrective**: nothing in the corpus is wrong by its own stated rules, and a requirement added now is predicted to be honoured exactly as faithfully as everything already there.

The engine's content is settled, from `.ai-factory/handoffs/28-the-polymorphism-engine-and-what-it-would-feed.md`, and this phase does not re-derive it. **The question**, put as the open/closed principle rather than as any invented threshold: *to add a third kind, how many places must change?* One place — the site that constructs — is correct on its own terms; more than one means the distinction was never actually polymorphic, whatever the type signatures suggest. **The trigger**: the arrival of the second invariant — an event, not a count of branches and not a threshold, so before the second invariant there is nothing to do and after it there is exactly one question to ask. This is also why the unit carries no single-responsibility principle beside its own question: SRP is a virtue, true or false at every moment equally, and a principle true always fires nowhere, while the unit's whole value is that it has a *moment* instead. SRP is dropped for this structural reason, not because it was proposed and then reconsidered — handoff 28, searched again for exactly this, never names the principle; it carries the spaghetti-code framing the user described, never single responsibility by name. **The exemption**: the constructing site is never itself a finding — branching before the object exists is construction, branching after it, on a field the object already carries, is the smell. **The vocabulary**: classical, cited rather than re-derived — a conditional over a type code replaced by polymorphism; a type-code field itself replaced by subclasses, by state, or by strategy; and, for the data-side twin of the same smell, illegal states made unrepresentable. Default: no finding at all; it fires only on the event, never on style.

One lens, two selectors, sharing the same question and differing only in how the region under examination is chosen. The **time** selector takes what a diff just landed: does this change bring a second member to a kind, and was a seam cut at that arrival or not — its evidence is the diff. The **space** selector takes a named region with no diff to trigger it — a module, a directory, a class — and inventories the kinds *declared* there (a union of two or more members, an enum, a boolean field naming a mode, a set of subclasses), asking the same question of each. This is what lets the engine run with no task in front of it at all, pointed at a region that simply reads badly.

`roadmap-decompose-skeleton` is the phase's named consumer, because its own Lens 1 already does this work by judgement where the engine would do it by event: "Scan the target task(s) for a shared type/interface surface — shared between 2+ tasks, or a single task whose shape is non-obvious — where an interface / abstract-class skeleton genuinely makes the surface testable." That justification is testability, not shared shape: Lens 1 cuts a seam because the result becomes testable, and the engine's own question — does a third kind cost more than the one place obliged to change? — is a different reason entirely. Replacing that description therefore changes the *reason* a seam is cut, not merely its wording — the sharpest fact in this phase. The engine's event — does this task bring a second member to a kind? — replaces "non-obvious" with a checkable fact; where it fires, the skeleton task *is* the seam, exactly as `test-philosophy`'s discriminator today replaces judgement in the same skill's Lens 2.

`docs/sakshi-harness/skill-cycle.md` describes this same pass by one axis only — специфицируй тихо-падающую поверхность прежде, чем её писать (specify the silently-failing surface before writing it), plus the feedback edge that returns an under-specification the skeleton pass surfaces back into the governing spec — and never names a shared-surface axis at all; that is the documentary divergence this phase creates and must close, and no new document is written here to close it.

With `command-pin-gaps` out, one skill loads the unit: `roadmap-decompose-skeleton` alone. The family's own rule for factoring a capability into its own skill — `.ai-factory/ARCHITECTURE.md` § "Composition: mechanism vs policy," restated in `CLAUDE.md`: "Factor a capability into its own skill only when it carries shared content... used by ≥2 callers" — asks for two or more, and one alone does not, by that rule, justify a separate file. The second caller here is the user himself: his own standing ruling is that a philosophy unit invoked directly, with a named region, needs no thin lens over it — "Я могу сформировать эту часть инпута сам, если вызову философию тестов и укажу область в коде и скажу что вызывает у меня подозрения, агент легко справится." That makes this a philosophy unit that is also directly invocable — the same arrangement `test-philosophy` already has (`user-invocable: true` in its own frontmatter) — said plainly so nobody later builds a one-caller engine by accident, or deletes this one for being one.

The user's own invocation practice remains a true fact about how he works, independent of this phase: the skeleton is always called for a whole phase, seeing a phase's entire set of kinds before any of it lands; `command-pin-gaps` is always called for a single task, seeing one task's change against code that already exists. Neither half of that fact makes `command-pin-gaps` a consumer of this unit. The user ruled it out, and gave no reason: "не знаю почему, но не хочу." A ruling given without a reason is still a ruling; it is not reconstructed here, and it is not left standing as a candidate for a later phase.
