# Phase 49 — the container is per head, and the content is not

The governing spec's settled zone: "the working discipline, the rulings the user has made about how the pair works, the method learned from repeated failure, and the register of where the skills still lag the practice." Its live zone: "the editor's handle, the architect's current read of an open question, a diagnosis still forming." `agent-architect`'s own statement of what the buffer is for: "the editor's handle, any pairing role the user has assigned for the session, and the deferral entries below." Only the editor's handle appears in both. The spec names categories the skill does not; the skill names two — a pairing role and deferral entries — that appear in neither zone list, and the skill calls the second of those the buffer's primary content. This is an absence in the authoritative enumeration, not a stated contradiction — the spec never says deferral entries do not belong; it simply never names them.

The local measurement, kept as a proportion: deferral entries are 24.3% of this architect's own buffer; the rest is the Live zone's framing and the whole Settled zone. The "primary content" claim is false here as well as in the field report's repository — this is the one place in the run where a number earns its keep, because the claim it tests is itself a claim about proportion.

The drain rule, quoted from both spec and engine — "A ruling recorded in the buffer is a debt against the skill, not a record of one. It leaves the buffer when it reaches the artifact that should hold it" — governs exactly one kind of content: a ruling, which has a destination artifact it owes itself to. A per-unit record of what a pass found and closed has no such destination — nothing says when it leaves, because nothing names it as buffer content at all. No skill body and no document anywhere describes such a ledger; the only place the concept exists is the field report.

The lifecycle states two cases: "A head that begins from such a snapshot works in the buffer it names — the same memory, resumed, not a new one under an old name. A head that begins with no such pointer is a new head: it creates its own buffer first." The third is unwritten. A head that ends with no further snapshot leaves its settled zone where it sits, and nothing in the text carries that content anywhere. The spec describes the content as durable and the container as per-instance, and states no bridge between them.

The mismatch's cost, measured today: `.ai-factory/notes/` in this repository holds seven architect buffers, six of them belonging to other heads, and no architect reads another's. If the settled zone is the pair's durable shared context, then project-scoped discipline is sitting locked inside six containers scoped to heads that have ended, unreadable by rule. That cost is already paid, whichever way the question is ruled.

What each answer would require, without choosing: for a staging area, every current member needs an owning artifact to drain into, and the drain rule would have to be extended to name deferral entries and a ledger explicitly or to exclude them from the buffer — the per-instance file boundary is then correct as it stands, because nothing durable is meant to remain. For durable shared context, the file boundary is what has to change: a per-session, per-head-numbered file cannot serve as project memory without a continuation mechanism the spec does not have, its only two cases being resume-by-snapshot or start-empty.

No document besides `docs/paired-loop.md` describes the architect's buffer. Nothing under `docs/` is written.
