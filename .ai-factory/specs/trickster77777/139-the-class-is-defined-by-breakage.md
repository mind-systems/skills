# Phase 45 — the class is defined by breakage, and prose does not break

The class as it stands: "what the repository already contains that this change breaks — a caller, a format, an assumption elsewhere in the code that the change invalidates on contact." Argued from its own words: each named member fails mechanically and immediately — a caller errors or misbehaves, a format fails to parse, an assumption in the code produces wrong runtime behavior once violated — and prose that becomes false does none of it. Nothing errors, nothing fails to parse, the build stays green; only a claim about the code stops being true. "An assumption elsewhere in the code" is where the boundary blurs: a comment's stated assumption is textually in the code, but its failure is delayed and human-mediated rather than on contact, so the stronger reading is outside.

The reason the exclusion costs more than it looks: a task spec can name a file as the implementer's ground truth, and nothing then holds that file's prose to the truth. The field's own carrier was exactly that — a canonical proto tree's header comment, pointed at by a different task's spec as the thing its implementer reads as ground truth, stating as law a model the phase deleted. The prose was promoted to the standing of a governing document by a spec, and carried none of a governing document's obligations.

The always-loaded layer's asymmetry: it governs the relation between a governing spec and its code — the docs lead, and a divergence is a defect to reconcile — while the one rule anywhere that names a code comment, "Comments never cite the plan layer," governs what a comment may not contain, never whether it stays true. Comments are named once, about something else, which is why the absence reads as coverage.

Nothing in `src/` or `docs/` says a change owns the prose describing what it changes.

This repository's own exposure is structural: the product here is prose, so a skill body is the artifact rather than a description of one, and a change to one skill's mechanism can leave a sentence in another stating the old one. The current state is clean: `agent-architect`, `editor.md`, `architect-editor-engine` and `architect-pairing-engine` were read whole against what phases 36 through 40 did, every heading checked against the places that cite it by quote, every added or rescoped mechanism checked at its landing site, and a direct sweep run for the pre-40 phrasings; no sentence still states a removed mechanism.

`docs/sakshi-harness/skill-cycle.md` restates the blast radius in the same code register, and no document anywhere describes how a change's reach over prose is judged. Nothing under `docs/` is written.
