# Phase 47 — what the note describes, and what the skill presupposes

The skill defines a phase note as what decomposition cuts tasks from, written from the divergence: "a short statement, in words, of what is not yet as the docs say — this and this — with links to those docs; that is the essence of the phase and what decomposition cuts tasks from." The failure this phase names — a note keyed one entry per task — is not reproducible in this repository. Both `Phase note:` pointers on disk — `114-buffer-not-yet-shared-memory.md` and `115-channel-not-yet-meaning-and-hands.md` — carry no task key and take no structure from their phase's task set; each is a single dense paragraph naming what diverges, closed by a plain pointer to its governing spec. The evidence for the failure is foreign, from the field report, not a local instance — stated plainly rather than implied.

The template frames the whole exercise as measuring against a document, with a one-line escape hatch for when none exists — "Where no doc says how it must be, the note says so in one line." The verbosity directive asks for grounding "in the docs and code read at Step 0," conjunctively, with no clean way to say grounded in the code alone. What this run actually produced, in kind rather than as one number: four of the six notes written before this one — 41, 43, 44, 45 — found no document describing the behaviour at all; one — 42 — found a document that exists and is itself defective, a different finding entirely and not an absence; one — 46 — was mixed by its own design, one shape with no document and one with a document lacking only enforcement. The escape hatch covers the template's question and not the directive's presupposition.

The engine question, recorded and not decided here: `roadmap-outline-deep` takes from `roadmap-engine` only the roadmap format, the counting formula, the named-roadmap resolution, and the spec-destination routing. `roadmap-outline` and `roadmap-decompose` both instead run the engine's maintenance flow and declare all four hooks. Missing counterparts, named individually: no granularity hook declared; no per-entry gate declared, though the skill states the same answer in its own words ("there is no per-phase gate"); no update-mode actions and no menu to extend; no mode determination; no Create-mode draft-and-confirm cycle; no Check mode with anything to score. Two facts for the ruling: hooks (a) and (c) look reusable as they stand, and (b) is already the same answer in different words; hook (d) and Check mode are where the case weakens, because the engine's flow is built around confirm cycles and this skill contains no `AskUserQuestion` anywhere. The absence is not only a mismatch: the other two callers confirm before they write, and this one rewrites preambles and mints files with no confirmation step of its own — in this run the confirmation came from the architect by hand, which is nowhere in the skill.

The budget, newly measured. Step 2 says to rewrite the preamble to "~200–500 characters... keeping the phase's gate and its `Phase note:` pointer," and never says whether the pointer counts toward the budget. Measured over the six preambles this run rewrote: counted whole, pointer included, four of six exceed 500 — phases 43, 44, 45 and 46, each between 512 and 582; counted as prose alone, none do, the widest at 421. The pointer itself runs from 131 to 160 code points across the six. The budget's scope is decided by nobody, and the same sentence both sets the number and leaves open what counts toward it.
