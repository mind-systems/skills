# Plan: 28.1 — `roadmap-outline-deep`: a second pass that gives a drafted phase a note and a contract-line preamble

## Context
The phase tier has no second level: `roadmap-outline` drafts a header plus prose intro and stops, so the preamble absorbs note-sized prose (observed 1200–1900 chars). This task adds `src/skills/roadmap-outline-deep/` — a second pass over already-drafted phases that writes each one a phase note through `note` and compresses its preamble to ~200–500 characters closed by an inline `Phase note:` pointer — wires it into `active/skills/` and both `CLAUDE.md` enumerations, and gives `roadmap-prune` the one capture that makes the note's lifetime symmetric with a task spec's.

- [x] **Write the skill body: the phase note through `note`** (depends on Write the skill body: dependencies, targeting, workflow)
  Files: `src/skills/roadmap-outline-deep/SKILL.md`
  The note is written through `note` with all three of its caller hooks supplied:
  - **Destination directory** — the roadmap's own spec directory, the same destination and the same per-directory numbering task specs already use: `.ai-factory/specs/<slug>/` for a named roadmap, flat `.ai-factory/specs/` for the default roadmap. Both forms must appear literally in the skill body. This is `roadmap-engine` § "Spec destination" (`src/skills/roadmap-engine/SKILL.md:69-75`) routed through `note`'s existing destination hook — cite it, do not restate its mechanics, and introduce no new directory.
  - **Template** — a short statement, in words, of what is not yet as the docs say — this and this — with links to those docs; that is the essence of the phase. Never a copy of the doc. Where no doc says how it must be, the note says so in one line; the pass never writes under `docs/` and never invents a link.
  - **Verbosity directive** — short: a few sentences more than the preamble, grounded in the docs and code read at Step 0, a `file:line` where a claim needs one, never a transcript.
  The note is per phase; `note` returns the exact path, which Step 2 uses verbatim.
  **Re-run rule — one note file per phase, forever.** `note`'s Step 3 (`src/skills/note/SKILL.md:52-58`) only ever mints a *new* numbered file; it exposes no update-in-place path. Since this pass has no per-phase gate and a roadmap routinely grows new phases after a deepening pass, invoking `note` unconditionally would leave a superseded note behind on every re-run — orphaned the moment Step 2 repoints the preamble, and invisible to `roadmap-prune`, which captures only the path the current pointer names. That is verbatim the file-with-no-owner defect this task exists to remove. So: **where a phase preamble already carries a `Phase note:`, rewrite the note at the path that pointer names** (`Write`/`Edit`, already granted by the pinned `allowed-tools`) and leave the pointer byte-identical — `note` is invoked **only** for a phase that has no pointer yet. Never a second note file for one phase, and never a second `Phase note:` token in one preamble.
